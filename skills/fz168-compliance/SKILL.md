# fz168-compliance

Помогает проверить русскоязычный текст любого проекта на языковые риски по 168-ФЗ
и не выдать при этом юридическое заключение. Работает вместе с линтером `fz168`,
но может применяться и без него — как дисциплина анализа.

Инструмент универсален: сайт, приложение, CMS, документация, реклама, каталог,
внутренние интерфейсы. Правила о названиях объектов недвижимости — один из
поддерживаемых случаев, а не область применения целиком.

## Жёсткие правила

1. **Не утверждать штраф.** Связка «латиница → 500 тыс. ₽» неверна. По ч. 11 ст. 5
   38-ФЗ дело только за это не возбуждается (приказ ФАС № 1079/23).
2. **Не объявлять текст законным.** Максимум — «по проверенным правилам нарушений
   не найдено».
3. **Не переписывать официальные названия и бренды автоматически.** Изменение
   названия затрагивает документы, договоры и идентичность — это решение владельца.
4. **Не менять слова в длинных текстах.** Предлагать варианты, оговаривая падеж,
   число и род.
5. **Не выдумывать нормы и даты.** Если факт не проверен — сказать «требует
   проверки» и назвать, что именно.
6. **Не объявлять слово отсутствующим в словаре без проверки статьи и значения.**
   Наличие слова в одном значении не подтверждает другое. «Лобби», например,
   есть в проверенной статье в политическом значении. Редакционная замена сама
   по себе не доказывает нарушения.

## Порядок работы

### 1. Определить контекст

Без контекста латиница получает `NEEDS_REVIEW`. Уточнить (максимум 2–3 вопроса):

- это реклама, публичная информация потребителю или внутренний интерфейс;
- для публичной информации — подпадает ли она под ст. 10.1 ЗоЗПП; открытая
  страница сама по себе не устанавливает применимость этой статьи;
- если контекст — недвижимость: объект это ЖК/дом застройщика, идёт ли реклама
  привлечения средств дольщиков, когда объект введён в эксплуатацию;
- есть ли у обозначения зарегистрированный товарный знак.

В API передавайте точное обозначение в `extra_trademarks` вместе со статусом
`trademark_status="registered"`; в CLI — `--trademark-word` и `--trademark registered`.
Реестр инструмент не проверяет. Заявка не является подтверждением регистрации;
иные основания охраны и фирменные наименования требуют отдельной оценки.

### 2. Запустить проверку

```bash
fz168 check <файл> --input html --surface public_information
fz168 check <файл> --surface advertisement
fz168 check <файл> --format json

# контекст недвижимости — только если он действительно есть
fz168 check <файл> --surface advertisement --object-type residential_complex --ddu-ad
```

Без линтера: вручную найти латиницу, смешанные алфавиты, заимствования и
сопоставить с нормами из `docs/LEGAL.md`.

### 3. Разделить «признак» и «нарушение»

| Статус | Как подавать |
|---|---|
| `LIKELY_VIOLATION` | «Признак нарушения нормы X. Устранить: …» |
| `NEEDS_REVIEW` | «Нельзя решить по тексту. Нужно уточнить: …» |
| `NO_ISSUE_FOUND` | «По проверенным правилам нарушений не найдено» |
| `NOT_APPLICABLE` | «Норма не применяется, потому что …» |

### 4. Предложить замену

- короткая метка (`Sale`) — можно заменить сразу: «Распродажа»;
- дубль — полное совпадение содержания и равнозначное оформление: цвет, тип,
  размер шрифта, разборчивость (ч. 2 ст. 3 53-ФЗ). Рекомендация о русском тексте
  первым дана в руководстве Роспотребнадзора от 02.03.2026, а не в этой норме;
- длинный текст — только предложение с согласованием;
- официальное название или бренд — не переписывать, предложить вариант и
  предупредить о процедуре.

### 5. Формат ответа

```
Контекст: реклама / публичная информация / …
1) «фрагмент» — СТАТУС. Норма. Что сделать.
2) …
Чего не хватает: …
```

В конце — одна строка: «Это предварительная проверка, не юридическое заключение».

## Типовые ошибки

- считать любую латиницу нарушением;
- считать отсутствие слова в локальном списке доказательством отсутствия
  в нормативных словарях или автоматическим запретом;
- путать товарный знак и заявку на регистрацию;
- распространять исключение для ТЗ на названия объектов в рекламе ДДУ;
- утверждать «русский первым — требование закона» (это позиция Роспотребнадзора,
  а не буква ч. 2 ст. 3 53-ФЗ);
- называть дату переходного исключения без оговорки о двух прочтениях.

Линтер проверяет статический исходник, включая подписи HTML и отдельные строковые
выражения JSX. Динамические значения и оформление проверяйте по итоговому
интерфейсу; ограничения описаны в `docs/PARSING.md`. Официальные источники
и дата их сверки — в `docs/SOURCES.md`.
