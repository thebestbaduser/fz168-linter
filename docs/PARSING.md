# Проверка исходной разметки

Детектор сохраняет длину исходного текста и переводы строк. Позиции находок
указывают на исходник, включая значения HTML-атрибутов и строки в JSX.

Во всех форматах адреса с `http://`, `https://`, `www.` и адреса электронной почты
исключаются из проверки. Текст ссылки, подпись кнопки и другие видимые слова
продолжают проверяться.

Для HTML и JSX проверяются текстовые узлы и статические значения `placeholder`,
`title`, `alt`, `aria-label`, `aria-description`. У `input` проверяется `value`
для типов `text`, `search`, `email`, `tel`, `url`, `button`, `submit`, `reset`,
а также без явного `type` (тип по умолчанию — `text`). Значения `hidden`,
`password`, `checkbox`, `radio` и технические атрибуты не проверяются.
Комментарии и содержимое `script`/`style` скрываются.

В JSX поддерживаются отдельные статические строковые выражения, например
`<button>{"Sale"}</button>` и `<input placeholder={'Sale'} />`, включая строки
в обратных кавычках без интерполяции. Динамические выражения, вызовы функций,
условные ветки и строки с интерполяцией не вычисляются. Для проверки их результата
нужно передать итоговый текст или отрендеренный HTML. Это разбор фрагментов
разметки, а не полноценный парсер JavaScript/TypeScript: файлы компонентов целиком,
регулярные выражения JavaScript и вложенный JSX внутри выражений не поддерживаются.

HTML-сущности (`&nbsp;`, `&amp;`, числовые ссылки) скрываются как синтаксис,
чтобы их имена не превращались в ложные латинские слова. Они не декодируются:
слова, частично или полностью записанные сущностями, нужно проверять после
декодирования отдельно. Аналогично JavaScript-последовательности экранирования
не преобразуются в символы. Это ограничение сохраняет точность исходных позиций.

Детектор не вычисляет CSS, состояние DOM и доступные имена по `aria-labelledby`.
Наличие статической подписи в исходнике само по себе не доказывает, что она видна
пользователю или соответствует требованиям к оформлению и переводу.
